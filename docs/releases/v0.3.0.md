# CC v0.3.0 — Opt-in workspace worktrees

`cc work` now launches in the registered clone by default. Workspaces that want
isolated Git worktrees can enable them once in `workspace.json`:

```json
"worktrees": true
```

- Missing or `false` uses the clone's current checkout.
- `--worktree` and `--no-worktree` override the workspace setting for one run;
  they cannot be passed together.
- Both modes record the actual branch in ticket state and display it in
  `cc show`. Launch output includes the working path, branch, and a quoted,
  ready-to-run `git log` command.
- Checkout mode preserves the current branch and uncommitted changes. It does
  not create or switch branches, apply `--base`, or fetch. To prepare a branch
  yourself, run `git -C /path/to/repo switch -c cc/ticket-id origin/main` with a
  verified local base ref before launching. `--base` applies only to a new
  worktree branch; worktree mode also does not fetch automatically.

## Breaking change for existing workspaces

An existing workspace with no `worktrees` key now uses the clone. To keep the
previous behavior, add `"worktrees": true` to its existing `workspace.json`
object before updating, or use `--worktree` for individual launches.

`cc upgrade` preserves configuration and ticket records; it does not infer or
migrate this setting. Existing worktrees stay on disk and can be reused after
opting in. The default worktree base remains `../.cc-worktrees`.

## Update

Run in Claude Code:

```text
/plugin marketplace update my-cc-marketplace
/plugin update cc@my-cc-marketplace
/reload-plugins
```

Restart Claude Code if your installed version requires it. Keep using the same
workspace; do not rerun `/cc:init`. Existing tickets, plans, and context remain
local. Plugin Skills use the updated bundled engine immediately after reload.
Run `/cc:upgrade` to refresh the workspace's standalone `.cc/cc` engine as well;
request `/cc:upgrade --refresh-skills` to refresh unchanged generated standalone
Skills. Customized Skills are preserved.
